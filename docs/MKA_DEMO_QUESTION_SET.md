> 「製造業有個老問題：知識都在老師傅腦袋裡、規格都在業務的 Excel 裡、SOP 都在沒人翻的文件櫃裡。今天展示的系統叫 Enclave MKA——它讓每個職務的人，用自己的方式（講話、掃碼、打字）把知識放進來、取出來，而且**每一句回答都有出處、每一次寫入都有簽核**。我們直接看三個真實工作情境。」

## 第一幕：業務的一天（約 5 分鐘）

**登入 `sales@demo.mka`**（一般視窗）

### 1-1 工作台（30 秒）

- **動作**：登入後停在業務工作台，手指著畫面
- **台詞**：「登入看到的就是『業務的工作台』——不是制式首頁。系統知道他是業務，所以入口是報價、規格查詢、待辦。換個職務登入，長得不一樣。」

### 1-2 版本差異問答（60 秒）

- **動作**：點「查規格／SOP」（或問答），輸入：

```
P-200 的 v2.0 和 v2.1 規格差在哪？
```

- **等待時台詞**（回答約 10–20 秒，別冷場）：「它在幾千段文件裡找三份不同版本的規格書來比對——這不是關鍵字搜尋，是語意理解。」
- **預期畫面**：列出 3 項差異（IP54→IP65、工作溫度 -20–70 °C、新增 CAN bus），下方附來源《D01c 產品規格書》
- **台詞**：「注意兩件事：第一，它**比對了兩個版本**；第二，每個說法都**標了出處**——業務回答客戶前可以點進去確認原文。」

### 1-3 詢價（60 秒）

- **動作**：接著問：

```
翔展科技要買 P-200 300 pcs，單價大概多少？有 MOQ 嗎？
```

- **預期畫面**：量購級距 NT$1,150/pcs、總價 NT$345,000、MOQ 50、引用《D04 價格政策》
- **台詞**：「它找到價格政策裡的級距表，自己算好總價，還提醒 MOQ 和有效期限。新進業務不用背價格表了。」

### 1-4 任務工作區開報價單（90 秒，本幕高潮）

- **動作**：回工作台 → 點「開報價單」→ 進入 **任務工作區**（網址應是 `/job/tasks/quote`，不是舊的表單頁）
- **首選（穩）**：在「用說的或打字」輸入框貼上（或口述後改打字）：

```
幫翔展科技報價，料號 P-200，三百個，單價一千一百五十
```

  再按送出。語音備案（麥克風）：

> 「欸，翔展科技剛才來電話，他們要 P-200，三百 pcs，問什麼時候能交。價格就照上次那個級距。」

  （完整逐字稿：`test-materials/A-sales/A3_語音腳本_詢價口述.md`）

- **預期畫面**：右側「欄位確認」出現客戶＝翔展科技、料號＝P-200、數量＝300、單價＝1150，來源標「文字」或「語音」；缺的必填欄位會黃框提示
- **台詞**：「注意——這不是傳統表單。業務**用講的或打一行話**，系統先抽出欄位給你確認；完整表單只是備援。沒聽準的欄位標出來請你改——不會硬猜。」
- **動作**：補齊必填（付款條件、有效期限等可手動改）→ 按「送出審核」
  - 必填齊全時：系統建立表單**並送進主管審核收件匣**
  - 還缺欄位時：只建草稿，黃框提示補完再按一次
- **備援**：右下「檢視完整表單（手動備援）」才進 `/forms/quote`——demo 主線不要走這裡

### 1-5 主管核准＋匯出（60 秒）

- **動作**：切到**無痕視窗**（admin）→ 審核中心 → 看到剛才的報價單 → 點「核准」
- **動作**：切回 sales 視窗 → 回到任務工作區或「我的表單」→ 狀態變已核准 →「匯出 PDF／DOCX」
- **預期畫面**：公司格式的正式報價單（有公司抬頭、表格）
- **台詞**：「送審、主管一鍵核准、匯出就是**公司自己的版型**——從一通電話到正式報價單，兩分鐘，全程有紀錄。」

## 第二幕：現場的五分鐘（約 5 分鐘）

**登入 `field@demo.mka`**（一般視窗登出 sales，換 field）

### 2-1 掃碼進場景（45 秒）

- **動作**：工作台 → 掃碼（QR 或手動輸入 `EQ100-DEMO-QR-001`）
- **預期畫面**：進入「EQ-100 高速捲繞機（二廠 A 產線）」場景，畫面上有場景標示
- **台詞**：「現場人員走到機台旁，掃機台上的 QR Code——系統就知道你站在哪台機器前面。接下來的問題，**自動限定在這台設備的資料裡找**。」

### 2-2 異常代碼問答（60 秒）

- **動作**：在場景狀態下問：

```
E-07 怎麼處理？
```

- **預期畫面**：先講安全（立即停機、**禁止強制復歸**）再講排查步驟，引用《D02 操作與保養 SOP》
- **台詞**：「注意它**先講安全、再講步驟**——這是 SOP 裡的順序。新人半夜遇到異常，不用打電話吵醒師傅。」

### 2-3 任務工作區異常回報（90 秒）

- **動作**：回工作台 →「異常回報」→ 進入 `/job/tasks/incident` → 打字或麥克風：

```
EQ-100 剛才跳 E-07，張力一直飄，我停機檢查了，張力計實測比設定值高了快兩牛頓，麻煩設備課來看一下。
```

  （完整逐字稿：`test-materials/B-field/B3_語音腳本_異常口述.md`）

- **預期畫面**：欄位確認卡出現現象描述；若先前掃過碼，設備相關欄位應帶場景上下文
- **台詞**：「現場人員戴著手套也能回報——**講一句或貼一段**，系統先抽欄位給你確認再送審。」
- **動作**：補齊必填 →「送出審核」（admin 視窗可即時核准，或留著說「流程同第一幕」）

### 2-4 交接班（45 秒）

- **動作**：工作台 →「交接班」→ `/job/tasks/handover` → 填兩三個重點（可照上面異常事件講）→ 送出審核
- **台詞**：「下班前把今天的事留給下一班。這些紀錄都進知識庫——**下次有人問『這台機器以前怎麼了』，系統查得到**。」
- **備註**：完整表單頁 `/forms/shift_handover` 仍可用，但 demo 主線走任務工作區。

## 第三幕：老師傅的經驗留下來（約 7 分鐘，全場重頭戲）

**登入 `master@demo.mka`**

### 3-1 訪談建卡（120 秒）

- **動作**：工作台 →「訪談建卡」→ 進入 `/job/tasks/interview`（或備援 `/knowhow/interview`）→ 開始 → 用講的或貼上逐字稿，內容大意：

> 「E-07 張力異常喔，我做二十幾年了，通常都是先看一下張力設定有沒有跑掉。老做法是用目測、用手感去判斷張力……」

  （完整逐字稿：`test-materials/C-knowhow/C1_語音腳本_師傅訪談逐字稿.md`）

- **預期畫面**：系統自動抽出「處理步驟」「注意事項」「適用設備」，組成一張知識卡草稿
- **台詞**：「師傅不用學打字、不用學文件格式。**用講的，系統幫他整理成結構化的知識卡。**」

### 3-2 SOP 衝突攔截（90 秒，全場最有記憶點的一幕）

- **動作**：檢視卡片 → 按「送審」
- **預期畫面**：**被擋下來**——畫面顯示「發現 2 項與 SOP 的衝突」：卡片建議「目測／手感判斷張力」，但 D02 SOP 明文禁止
- **台詞**：「注意看——系統**不讓這張卡過**。為什麼？師傅二十年前的做法，跟現行 SOP 矛盾。以前這種矛盾會靜靜流傳，新人學了舊做法就出事故。現在系統把它**抓出來、攤開給你看**。」
- **動作**：在衝突項目上標記處置（如「已確認：以 SOP 為準，移除目測做法」）→ 再次送審 → 通過

### 3-3 主管核准（30 秒）

- **動作**：無痕視窗 admin → 審核中心 → 核准這張卡
- **台詞**：「知識要**核准才會上線**——品質有把關。」

### 3-4 新人查得到（60 秒）

- **動作**：一般視窗登出，**登入 `newcomer@demo.mka`** → 問：

```
機台張力異常怎麼辦？
```

- **預期畫面**：回答引用**剛才那張師傅卡**（來源顯示 knowhow:張力異常（E-07）…）＋ SOP
- **台詞**：「三分鐘前師傅講的話，新人現在就查得到。而且——**沒核准的草稿，新人是查不到的**；我們剛才親眼看到它被擋下來過。」

## 收尾（60 秒）

### 4-1 它不會硬掰（信任收尾）

- **動作**：任一帳號問：

```
P-300 的規格是什麼？
```

- **預期畫面**：明確回答「知識庫中沒有 P-300 的資料」，並列出現有相關文件
- **台詞**：「最後一個展示：我們根本沒有 P-300 這個產品。它不會為了回答而**編造規格**——找不到就說找不到。這是企業用 AI 最重要的一件事。」

### 4-2 權限（30 秒，可省略）

- **動作**（有時間才做）：登入 `viewer@demo.mka` → 左側選單沒有管理功能；直接打管理網址會被擋
- **台詞**：「權限是分層的——老闆看的、現場看的、新人看的，不一樣。」

### 4-3 結語

> 「總結今天看到的三件事：一、**知識有出處**——每句話都能點回原始文件；二、**動作有簽核**——報價單、知識卡都要主管核准才生效；三、**矛盾會被攔**——老經驗跟現行 SOP 衝突時，系統會抓出來。知識跟著公司走，不跟著離職信走。」

## 救場備案（出事時怎麼辦）

| 狀況 | 處理 |
|------|------|
| 回答超過 20 秒還沒出來 | 正常現象（CPU 運算），台詞：「它在讀幾千段文件，給它十秒鐘。」超過 60 秒就重新整理重問 |
| 回答說「找不到資料」但你確定有 | 換個問法，把**型號、檔名關鍵字**講出來（例：「EQ-100 的維修紀錄有哪些？」比「之前出過什麼問題？」穩） |
| 語音辨識失敗／麥克風沒反應 | 檢查瀏覽器麥克風權限；**立刻改貼文字備案句**，台詞：「現場網路或環境音太吵時，也可以打字——這就是任務工作區的設計。」 |
| 點「開報價單」卻進到舊表單頁 | 硬重新整理一次（部署後舊 shell 快取）；網址應是 `/job/tasks/quote`。仍錯就走「檢視完整表單」備援，但說明這是備援路徑 |
| 欄位只抽出客戶／料號，付款條件沒出來 | 預期行為：regex 抽取先顧高頻欄位；手動補付款條件／有效期限後再送審——台詞：「關鍵欄位它抽，其餘你確認——人工還是主角。」 |
| 掃碼沒反應 | 用手動輸入 token：`EQ100-DEMO-QR-001` |
| 審核中心沒看到單據 | 確認已按「送出審核」且必填補齊；確認 admin 與送審帳號同租戶；重新整理 |
| 整個網站打不開 | 先開手機熱點試試；還是不行就跳到紙本備案：展示 `docs/MKA_UX_TEST_SCRIPTS.pdf` |

## 給演出者的私房提醒

1. **先暖機**：觀眾進場前先問一題（§0.3），第一題最慢
2. **等待時不要沉默**：每題 10–20 秒等待是常態，台詞都幫你寫好了
3. **第三幕是重頭戲**：時間不夠就壓縮第一、二幕，SOP 衝突攔截一定要演到
4. **主路徑口號**：講「任務工作區／用講的帶入／表單是備援」，不要講「打開表單自己填」
5. **觀眾想亂問**：引導往「P-200、EQ-100、報價、E-07」；問太遠得到「找不到」也是正確行為
6. 完整三劇本（含 UIUX 觀察點、評分表、權限測試）見 `docs/MKA_UX_TEST_SCRIPTS.md`

客戶要求 IP65、-20°C 工作溫度、CAN bus，P-200 哪個版本符合？
