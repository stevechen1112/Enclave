# Enclave 流程能力地圖（Pipeline Strength Map）

> **歷史時點文件（建立於 2026-08-06）**：本地圖保留當時部署與盲測判定，其中格式、OCR、RLS 與部署數字可能已被後續架構取代。2026-08-28 起，Input Platform 現況以 `INPUT_PLATFORM_CAPABILITY_MAP_AND_IMPLEMENTATION_PLAN.md`、runtime capability contract、sealed corpus manifest 與最新 Phase Review 為準。

> **目的**：把整條流程「哪裡強、哪裡弱、哪裡還沒驗證」集中在一份文件，對內指導施工優先序，對外支撐誠實宣稱。
> **性質**：活文件。每次盲測、E2E、部署或客戶試用後更新；每列必須附證據連結，不許憑印象改評級。
> **建立**：2026-08-06（整合 STAGE_SUMMARY_2026-08-05、OPEN_GATES、Z3/Z4 盲測、Linode 部署實績與當日生產 E2E）

## 評級定義

| 評級 | 意義 | 宣稱紀律 |
|------|------|----------|
| **強** | 有獨立證據（盲測／閘門／上線實績），可對外宣稱 | 可寫進對外材料，附數字 |
| **中** | 可用且有驗證，但存在已知弱點 | 可展示，但須主動揭露限制 |
| **弱** | 已知問題未解，或只在有利條件下成立 | 不可對外宣稱；內部列改善項 |
| **未驗證** | 連強弱都不能談（缺真實條件） | 禁止任何形式的宣稱 |

## 一、主流程地圖（文件進來 → 答案出去）

```
入庫上傳 → 解析/切塊 → 索引(向量+BM25) → 查詢規劃 → 多臂檢索 → 融合/上下文組裝
→ 生成(含拒答) → 引用驗證 → 回答呈現
```

| # | 環節 | 評級 | 證據 | 已知弱點 |
|---|------|------|------|----------|
| 1 | 入庫上傳（文字檔/MD） | **強** | 22 份測試文件全入庫（2026-08-06）；FD-DELIVER 閘門防假成功 | — |
| 2 | 掃描 PDF／圖片入庫 | **弱** | LlamaParse 關閉（Linode 8GB 取捨） | 掃描件不支援；表格/掃描金額穩定度是 Z4 後明列改善項 |
| 3 | 真實客戶格式（DOCX/XLSX/混排 PDF） | **未驗證** | OPEN_GATES「真實客戶版型比對」需客戶檔案 | 測試語料多為精心排版 MD，真實文件解析品質未知 |
| 4 | 索引（向量 bge-m3＋BM25） | **中** | Z3/Z4 檢索命中支撐 78–79% | BM25 每查詢全量載入記憶體重建索引，大庫（數萬 chunk）有效能風險 |
| 5 | 查詢規劃（QueryPlan 意圖/多臂） | **強** | FD-QUERYPLAN 閘門 PASS；複合盤點 multi_hop | 檔名錨定對自然問句偏積極，可能排除相關文件（2026-08-06 翔展案例） |
| 6 | 多臂檢索＋融合 | **中** | Z3 67/85、Z4 39/50 凍結基線 | Z4 凍結 fail：找錯檔（028 類）、金額漏招（017/020/046）、跨庫干擾（037 類）；問法敏感（彙整型問題） |
| 7 | 上下文組裝 | **中**（改善中） | 2026-08-06 修復：文件分組佔滿上下文 → 改分數排序＋每文件上限 2 段；scoped 檢索 semantic→hybrid | 修復未經 Z5 hold-out 驗證 |
| 8 | 生成（含拒答） | **強** | Z4 拒答 D 類 6/6；生產反例（P-300）正確拒答 | 依賴 OpenAI 單一供應商；仍需防過拒與漏拒 |
| 9 | 引用可追溯 | **強** | 回答逐句標來源可點回原文；citation 統一由 CitationBuilder 產出 | — |
| 10 | 回答延遲 | **中** | 生產實測 10–20 秒/題 | CPU embedding 物理限制；OLLAMA_KEEP_ALIVE=-1 已消除冷啟動（原 119s） |

## 四、絕對邊界（任何情況都不可宣稱）

1. 「敢讓客戶亂丟亂問都穩」——Point B 未達標（STAGE_SUMMARY 明列）
2. 掃描版 PDF 可入庫——目前不支援
3. 生產環境有病毒掃描保護——ClamAV 關閉中
4. 回答 100% 正確——78–79% 是誠實水位，重要決策須人工核對
5. MKA 工作流經過盲測——只有自製語料 E2E，無 hold-out 證據

## 五、下一步優先序（依本圖弱點排序）

1. **Z5 新 hold-out 盲測**：驗證 2026-08-06 兩個檢索修復（上下文多樣性、scoped hybrid）真的泛化——禁止只重跑 Z3/Z4 主集
2. **真實文件入庫驗證**：拿真實客戶 DOCX/掃描 PDF 跑入庫→問答全鏈（環節 2、3）
3. **語音實地測試**：真機＋工廠噪音＋中英夾雜料號（環節 13）
4. **BM25 索引持久化**：大庫效能（環節 4）
5. **生產安全補齊**：ClamAV 開啟（升 RAM 或獨立容器）、RLS FORCE、備份排程（環節 22、20、25）
6. **外部滲透**：商業閉環最後一個人工閘門（環節 26）

## 六、更新規則

1. **觸發時機**：盲測完成、E2E 走查、部署、客戶試用、code review 發現——任一發生即檢視本表
2. **改評級必附證據**：連結到 artifact／測試報告／文件章節；無證據的評級調整視同無效
3. **降級也要記**：發現新弱點導致降級是正常且必要的（誠實原則）；在變更紀錄寫明原因
4. **與其他文件的關係**：閘門狀態以 `OPEN_GATES.md` 為準；盲測分數以 `STAGE_SUMMARY` 與 `artifacts/blind_*/` 為準；本文件是**整合視圖**，不取代原始證據
