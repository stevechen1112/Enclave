# Owner 實際使用稽核與修復紀錄（2026-09-05）

## 目的

以八策股份有限公司 Owner 的正式登入工作階段，驗證產品是否能讓第一個租戶完成「看懂目前狀態、管理公司、確認來源、追溯操作與檢查服務」；不把 UI 可進入誤當成工作真的可完成。

本次檢視為唯讀：未核准、駁回、上傳、刪除來源或執行外部 Provider 實測。

## 已確認可用的基礎流程

| 範圍 | 實際結果 |
| --- | --- |

## 發現的真實缺陷與根因

### P0：公司與帳號頁面對 Owner 失效

前端誤把租戶 Owner 的「公司與帳號」頁接到平台超級管理員 `/admin/*` API。該 API 同時受超管與 IP 白名單限制，造成儀表板失敗，且成員管理的邀請、改角色、停用也會一併失效。

### P1：系統健康頁被單一受限請求拖垮

外部 AI Provider 設定被放在 `/admin/system/provider-health`；Owner 雖有租戶管理權，仍被平台 IP 白名單擋下。前端使用 `Promise.all`，導致原本獨立的資料完整性報告也一併不顯示。

### P1：人工確認對企業 Owner 洩漏工程表示法

候選類型、Provider、政策鍵、ACL、知識單元與 JSON 直接露出；在一般桌機寬度又擠成三欄，證據閱讀與決策都不實用。這會提高錯誤核准風險。

### P1：稽核記錄被相容性遙測淹沒

`legacy_surface_used` 是為了淘汰舊介面的工程遙測，資料本身應保留，但不應成為 Owner 預設畫面的主內容。原畫面也只顯示 UUID、完整 IP 與英文 action，無法回答「誰做了什麼」。

### P1：能力與應用目錄只顯示內部代碼

模組化架構是正確方向，但 `enclave_base`、`quality_8d`、`mka` 等代碼不能直接當產品文案；租戶無法據此理解核心能力與可選應用的關係。

### P2：知識品質頁容易和來源處理狀態混淆

「需處理」是正式知識版本的可用性，不是來源是否已完成解析；原文案沒有說清楚，易讓使用者以為數字矛盾。

## 修復範圍

### 租戶權限與資料契約

- `companyApi` 全數改用 `/company/*` 租戶自助端點；平台 `/admin/*` 仍保留給超級管理員，未降低平台隔離。
- `/company/dashboard` 回傳 UI 實際需要的使用者、有效文件、對話、本月 AI 問答與用量成本欄位。
- 新增 Owner/Admin 可讀、但不揭露密鑰的 `/company/system/provider-health`；實測仍必須顯式 POST。
- 健康頁改用獨立結果處理：Provider 暫時無法讀取時，資料完整性報告仍可用。
- Provider 實測改成二次確認，明示會有少量 API 用量，且不會上傳公司的知識來源。

### 工作台與治理呈現

- 人工確認將常見候選與政策鍵映射為中文業務語言。
- 預設只顯示可審閱內容、來源證據和人類可理解的發布條件；原始 JSON、ACL 與單元鍵移到「技術詳細資料」收合區。
- 部門 UUID 篩選歸為進階功能，不再以一般篩選項目誤導。
- 稽核 API 預設排除 `legacy_surface_used`，可用「顯示系統技術事件」取回；歷史遙測完全保留。
- 稽核回傳租戶內的執行者名稱或 email 顯示名，前端遮罩 IP，並提供分頁載入。
- 能力目錄顯示產品名稱與用途，內部識別碼只放在收合技術明細。
- 品質頁明示其統計對象只限已進入正式知識版本。

## 安全邊界

- 本修復不會自動核准、駁回、發布、刪除或重跑任何知識來源。
- Provider 健康檢查不在頁面載入時呼叫；必須由 Owner/Admin 二次確認。
- Owner 的租戶管理能力與平台超級管理能力仍分離；未將 `/admin/*` 放寬。
- 相容性遙測僅調整預設可見性，未刪除、未改寫稽核證據。

## 驗收要求

1. Owner 登入後，`/governance/organization` 顯示公司摘要並可讀取成員清單。
2. `/system/health` 同時顯示 Provider 設定與資料完整性區塊；不按確認不可發出外部實測。
3. `/knowledge/review` 在桌機與手機都先顯示中文候選、證據與發布意義；JSON 只在主動展開時出現。
4. `/governance/audit` 預設有商業操作，勾選後才出現系統相容性事件；執行者為可識別顯示名、IP 已遮罩。
5. `/system/modules` 顯示「企業知識核心」等產品名稱，並保留四維狀態的獨立性。
6. 進行發布前檢查：前端 build/lint、相關 Vitest、Python API/權限測試、release candidate workflow、部署後 edge health 與 Owner 瀏覽器復驗。

## 已知驗證限制

本機整合測試需要 PostgreSQL `pgvector`。目前本機 PostgreSQL 17 未安裝 `vector` extension，故涉及完整資料庫 fixture 的公司管理整合測試無法啟動；這不表示測試失敗或 API 行為失敗，但在發布候選 CI（具備既定容器依賴）必須通過後才能發布。
