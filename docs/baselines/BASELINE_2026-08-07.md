## Phase 0 已修復的雙軌問題

1. **capability 雙軌**：前端 `ROLE_CAPS` 有 `field_work`、後端 `_ROLE_CAPS` 沒有；且前端完全不看 bootstrap。
   現在 bootstrap 是唯一能力來源（`useCapabilities` hook），前端本地表僅為 route-guard fallback，
   parity 由測試把關。後端 `default_home` 與前端 `defaultHomePath` 規則一致（admin→overview、field_work→job、其他→ask）。
2. **模組 ACL 屬性不一致**：`ModuleRouter` 原只讀 stub 屬性 `roles`/`department_id`，
   chat runtime 傳入真實 `AuthorizationContext`（`role_ids`/`department_ids`）時模組 ACL 全部誤判無權。
   現由 `authz_role_ids`/`authz_department_ids` 正規化，`experience.py` 改用 `AuthorizationContext.from_user`。
3. **部門樹成環防護**：`AuthorizationContext.from_user` 祖先遍歷加深度上限 32。
