## 1. 「先射箭再畫靶」在本輪實際發生了什麼

### 1.1 已寫進 DESIGN 的禁令（正確）

- 禁止依 extract／系統回答命題或事後改 span  
- 禁止修洞後用同一失敗集當唯一滿分  
- 禁止檔名洩題仍當難題  

### 1.2 執行上已違反／實質等同違反

| 事實 | 證據 | 為何算畫靶 |
|------|------|------------|
| 先建 `extracts/` 再寫意圖題 | `extract_index.json` 40 筆早於／並行於 draft | 出題者可（且曾）看可抽字串 |
| 對話摘要：曾讀安可／Smat／醫美等 extract 再準備命題 | agent transcript／summary | 典型「看見才出題」 |
| 題幹寫「金流系統建置合約」 | draft z3-i-001… | hold-out 實際是「系統開發報價調整版」「委託合約-八策品牌」——**檔名被腦補** |
| 24 題幽靈客戶 | 心恬／富裔／大禾／愛玩客／禾餘／微碧／樂活… | 考卷指向未入選檔，分數無意義或逼系統拒答變水題 |
| z3-i-057 查統編 | draft | 即使用「財務意圖」包裝，仍是 Z2 式欄位抽取 |
| 同一 agent 兼出題／抽字／寫規範 | 流程 | 三角色分離在單人代理下**紙上有、實作無** |

**判定**：v1 draft 的 `anti_target_drawing: true` **名實不符**，應標 `contaminated: true`。

## 2. Hold-out 語料（40 檔）問題

### 2.1 組成（實際）

16 個「客戶」槽位，多數每客 3 檔：優利、光昱金屬、CYS、醫美圈圈、昇展Smat、安可、bravomix、瑪格麗特、MF Select、宏寰、優克美、巽耘；另有立壕線板、Dr.Kelly、阿里巴巴、以及誤把檔當資料夾的 `行銷傳播企劃.pdf`。

### 2.2 結構缺陷

1. **複本／近複本**：優利同名×2；安可報價調整版 docx×2；光昱亞馬遜提案×3；bravomix 規格簡報×2；MF／宏寰多版。DESIGN 要求「降權」**未執行**。  
2. **空抽取 ≈11/40**：extract 僅 `[empty]`——掃描件可當 OCR 壓測，但選檔是「檔名關鍵字＋大檔」，不是刻意 OCR 分層。  
3. **選檔演算法**：`build_blind_z3_corpus.py`＝關鍵字命中後每客最多 3、再取前 40。**不是**「意圖題寫完再決定上傳哪 30–50 份」（與 DESIGN §4.5 相反）。  
4. **Z2 排除不完整**：只排除少數檔名關鍵字；未排除「同模板八策報價」這類分布重疊。  

### 2.3 與意圖題對齊

- 約 **27** 題勉強碰到 hold-out 客戶名  
- 約 **9** 題客戶對但**文件類型腦補**（金流／官網）  
- 約 **24** 題**幽靈**（客戶不在 40 檔內；光昱別名誤判另計，真實幽靈仍約 20+）  

→ **不能拿 v1 去標 GT。**

## 6. 重置後才算遵守「先文件意圖、再答案」

正確順序（強制）：

1. **凍結語料清單**（只給：client / filename / ext / 是否疑似掃描）— 出題者**不准**開 extract。  
2. **只對清單上的檔**寫意圖題（可用資料夾名＋檔名推斷文件類型，**禁止捏造不存在的合約名**）。  
3. 配比達標後鎖定題幹 `intent_frozen: true`。  
4. **另一輪**才開原檔（或獨立 OCR）填 GT → `gt_frozen: true`。  
5. 上傳與**一次**評測；修洞用 `z3_debug` 探針，不回寫主集。  

單人代理時的最低替代：出題時工作目錄 ban `extracts/`；標註時另開 session／腳本只輸出 span、不改 question。
